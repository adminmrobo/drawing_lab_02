## 2. 원자료와 저작권

1. 원리는 スタジオ・ハードデラックス 『デジタルツールで描く！感情があふれ出るキャラの表情の描き方』(マイナビ, 2015) **4장 특별편 「髪の描き方」(p.135~158)** 을 참고한다(판권면으로 확인).
2. 책의 **그림·문장·도식·구성 순서는 옮기지 않는다**. 원리만 가져와 연구실 캐릭터와 직접 움직이는 실험으로 새로 만든다.
3. 책의 교복·맨몸 습작 예시는 쓰지 않고, 같은 원리를 **연구실 의상**(랩코트·후드티·카디건·메이드복·조끼와 넥타이)과 가발로 다룬다.
4. 수식·기법의 출처(ITU-R BT.601 밝기 무게, Marschner 외 2003·Kajiya·Kay 1989 머리카락 반사, Jakobsen 2001, RePaint 2022, 잠재 확산 모델 2022 등)는 각 페이지 바닥글에 적는다.
5. 원자료 출처는 목차 '원리와 출처'와 바닥글, README에 모두 밝힌다.

## 4. 등장인물과 역할

| 역할 | 캐릭터 | 쓰는 법 |
|---|---|---|
| 모델 | 하루(1·4부), 시아(2부), 모아(3부), 5부는 셋 모두 | 가발을 쓰고 머리 모양을 보여 준다. 한 부에 한 명이 주인공 |
| 손님 모델 | 박사(3·4부) | 흰머리 가발, 쓸어 올린 앞머리, 젖은 머리. 본문 그림에서는 꼬마 체형이 아닌 성인 남성 |
| 화가 | 주판봇 · 초파리 연구원 | 주판봇은 결과부터 서두르다 틀리고, 초파리는 원리부터 의심해 맞힌다 |
| 평가단 | X1 · X2 · X3 | 부마다 세 항목을 채점하고 한 줄 평을 남긴다. **X1 닮음**(분홍 사이드 포니테일, 밝고 성급한 첫인상파, 좌우 바뀜을 바로 알아챔) · **X2 원리**(베레모·청록 둥근 안경, 차분하게 이마 선·가르마·부피부터 따짐) · **X3 자연스러움**(고양이 귀 후드·노란 방울, 흔들리는 것을 좋아해 움직임·윤기에 예민) |
| 해설 | 박사 | 단계마다 현장 질문으로 열고, 결과를 해석하는 문장으로 닫는다 |
| 수식 질문 | 조수 하루 | 수식 상자에서 독자 대신 묻는다 |

- **모든 등장인물은 20대 성인**(박사는 성인 남성). 노출·과장된 체형·교복 느낌은 쓰지 않는다.
- 캐릭터 외형 고정값: 하루(정수리 번 2개 + 앞머리 가운데 남색 줄), 시아(흑발, 머리 장식 없음), 모아(흰 프릴 머리띠 + **왼쪽** 귀 위 흰 리본), 박사(흰 줄 있는 짙은 머리, 굵은 눈썹, 청록 사각 안경).
- 표정 그림은 저장소 `fruitfly-lab-expressions`의 캐릭터 그림을 쓴다.
- **변장 규칙:** 가발은 머리 모양만 바꾼다. 얼굴·눈 색(하루 파랑·시아 회색·모아 호박색)·옷·나이는 그대로, 모아의 흰 리본은 가발 위에서도 왼쪽 귀 위. 그림 요청문에는 `wearing a wig: … ; she keeps her own face …` 문장을 꼭 넣는다.

## 5. 한 부의 순서

1. 표지(픽셀아트) → 제목·한 줄 소개·글쓴이
2. **처음 오신 분께 — 세 줄 요약**: 무엇을 / 왜 알아야 하나 / 어디에 쓰나 + 낱말·약어 풀이
3. **오늘의 과제**: 박사·주판봇·초파리·모델의 짧은 대화 + 전체 흐름 띠
4. **단계 1~4** (6절의 틀)
5. **프롬프트로 직접 만들어 보기** (8절)
6. **평가**: 평가단 채점표, 합계, 박사의 해석
7. **정리**: 단계별 한 줄 · 식 · 작업 요령 표
8. **다음으로**: 다음 부로 넘어가는 대화와 링크
9. 지식 색인 · 온톨로지·서지 꾸러미 · 바닥글(출처)

## 6. 단계(실험실) 한 개의 틀

| 순서 | 상자 | 내용 |
|---|---|---|
| 1 | 제목·부제·방법·일상 꼬리표 | 제목은 결과를 우리말 문장으로("가르마는 이마 선보다 뒤에서 시작한다") |
| 2 | **왜 이렇게 하나** | 무엇이 문제인가 → 그냥 하면 막히는 곳 → 이렇게 푼다, 그리고 '쉽게 말하면' 한 줄 |
| 3 | **수식 상자**(필요할 때만) | 조수가 묻고 → 말로 하면 → 숫자로 한 번 해 보기(3줄) → 학교 수학으로 보면 → 식 → 식 조각 풀이 → 조수의 한마디 |
| 4 | 일상으로 치면 / 그림·VFX 현장에서는 | 생활 비유 하나, 실제 작업 사례 하나 |
| 5 | 대화 4줄 | 박사 질문 → 주판봇의 성급한 답 → 초파리의 실험 제안 → 모델이 결과를 숫자로 말함 |
| 6 | **실험 패널** | 직접 조작하는 SVG·캔버스 실험. 결과는 숫자와 문장으로 바로 보여 준다 |
| 7 | 해석 3줄 | 실험 결과 → 원리 → 작업 요령 |
| 8 | 그림(있을 때) | Genspark로 만든 본문 그림 |
| 9 | **AI 결과, 그대로 써도 될까?** | AI 그림에서 생기는 문제와 '답 보기' |
| 10 | **주의할 점** | 단순화한 가정과 예시값임을 밝힌다 |
| 11 | 확인 퀴즈 | 3지선다, 정답 해설과 힌트 |

### 수식 원칙
- 수식은 꼭 필요한 단계에만 넣는다. 넣으면 반드시 **숫자 예시 3줄**을 먼저 보인다.
- 기호 대신 말을 먼저 쓴다(예: '내적'이 아니라 'cos(사이각) > 0', 내적은 풀이 속 참고 낱말).
- 모든 숫자는 `build/check_numbers.py`로 검산한다. 예시값(세기 점수, 부드러움 계수, p 값 등)은 **예시값**이라고 본문과 바닥글에 밝힌다.
- 연습장의 숨은 보정값도 화면에 계산 과정을 그대로 보인다.

## 7. 문장 규칙

1. **우리말 어순, 번역투 금지.** 사물을 주어로 세우는 문장("공기가 만드는", "~이 말해 준다", "~이 정한다")과 "~에 대한", "~을 통해", "~의 이유" 같은 명사 나열 제목을 쓰지 않는다.
   - 예: '큰 그림 — 앞 부의 한계가 다음 부의 이유' → '전체 흐름 — 1부부터 7부까지 이어지는 순서'
   - 예: '앞 방법의 한계' → '그냥 하면 막히는 곳', '이 단계의 한계' → '주의할 점'
2. **금지어:** 연구실 스킬이 정한 금지어 세 개(`build/check_banned.py`에 글자 번호로 적어 둠)는 이 문서를 포함한 어떤 결과물에도 쓰지 않는다. 독자를 수학·통계를 포기한 사람으로 부르는 줄임말도 쓰지 않는다. 빌드 후 `check_banned.py`로 0건을 확인한다.
3. 낱말은 처음 나올 때 풀어 쓴다(접점, 여유율, 섬 그림자, 가림 영역 등은 '낱말·약어 풀이'에도 넣는다).
4. 학술적 주장을 하지 않는다. 원리와 실험, 작업 요령만 전한다.
5. 그림이 의도대로 나오지 않았으면 **있는 그대로 적는다**. 그림 설명(alt·캡션)은 실제 그림에 맞춘다.

## 8. 프롬프트로 직접 만들어 보기 (1~6부 필수)

부마다 평가 앞에 실습 2~4개를 둔다.

| 요소 | 방침 |
|---|---|
| A 프롬프트 | **이 페이지 그림을 실제로 만든 프롬프트**를 그대로 싣는다(`build/make_requests.py`가 원본). 복사 버튼과 첨부할 참고 그림 이름을 함께 둔다 |
| A 결과 | Genspark로 만든 실제 그림 |
| B 문장 | 원리를 하나 빼거나 바꾼 비교 문장. 'Same image. Change only: …' 형식으로 같은 대화에 이어 붙인다 |
| B 결과 | 실제로 만든 비교 그림(`docs/image_requests_make/`) |
| 결과에서 확인할 것 | 3개 항목, 각 항목에 해당 원리 단계로 가는 링크 |
| 실제 결과 | A·B를 나란히 보고 **실제로 무엇이 달라졌는지(또는 달라지지 않았는지)** 적는다 |
| 참고 그림 | `assets/refs/`의 기준 전신·설정 시트를 페이지에서 내려받게 한다 |

- 한 번의 요청에 여러 변화를 넣지 않는다. 단계는 같은 대화에서 하나씩, 구도가 흔들리면 'keep the same framing'을 덧붙인다.
- 같은 대화에서 차이가 약하면, 새 대화에서 처음부터 만들도록 안내한다.
- 머리(가발)만 바꾸는 실습은 설명용 그림이 아니라 도구의 **부분 수정(영역 칠하기)** 기능으로 한다.
- 실전 연습장 마무리에서 공방의 머리 문장을 실제 도구에 넣고 각 부 확인표로 점검하도록 연결한다.

### 프롬프트 연습 문제 (1~6부, 부마다 2개)
'직접 만들어 보기' 다음, 평가 앞에 둔다. 이 페이지 그림이 아니라 **새 장면**에 원리를 옮기는 연습이다(`build/content_ex.py`).

| 요소 | 방침 |
|---|---|
| 상황 | 모델·가발·장면을 한 문단으로. 이 부의 원리 1~2개만 쓰게 고른다 |
| 순서별 설명 | 3~5단계. 단계마다 '무엇을 적나 → 왜(빼면 생기는 실패, 6부 링크)' |
| 연습 프롬프트 | 예상 결과 그림을 실제로 만든 문장 그대로(`make_requests.py`의 CONV_EX), 복사 버튼·첨부 참고 그림 |
| 예상 결과 | Genspark 그림(`docs/image_requests_ex`). 오기 전에는 '그림 준비 중' |
| 확인표·실수 | 확인 3개(원리 링크) + 증상과 덧붙일 문장 표 + 바꿔 해 보기 |

## 9. 그림 방침

| 항목 | 방침 |
|---|---|
| 표지 8장 | **16비트 RPG풍 픽셀아트**, 16:9, 밝은 낮 연구실, 글자 없음, 얼굴·손은 가운데 안전 영역 |
| 본문 그림 | 이 시리즈만 **애니풍·반실사·실사풍** 허용(다른 시리즈의 픽셀 원칙은 그대로) |
| 실사풍 | 캐릭터를 코스프레한 **가상의 성인 모델**. 실존 인물과 닮으면 다시 생성 |
| 배경 | 흰색·밝은 바탕(사이트 배경도 흰색) |
| 금지 | 그림 안 글자·숫자·로고, 노출, 교복 느낌, 유명 캐릭터 이름·디자인 |
| 참고 그림 | 앞 시리즈에서 확정한 애니풍 기준 전신(`*_anime_base`)과 설정 시트를 매번 첨부 |
| 크기·형식 | WebP. 표지 1600×900, 가로 1200×675, 세로 600×900. 공유 미리보기는 표지에서 만든다(`make_og.py`) |
| 이름 | `checklist.csv`의 이름 그대로. 그림이 없으면 '그림 준비 중' 자리로 두고, 페이지는 그림 없이도 완성 상태 |
| 요청 단위 | Genspark 대화 하나 = 요청문 파일 하나(3~6장). 파일이 많으면 나눠서 요청 |

### 의도적 실패 그림
- 실패 8종은 **점검표의 다섯 항목**(① 뼈대 ② 다발·흐름 ③ 색·윤기 ④ 움직임 ⑤ 고정·가림 영역) 중 한 곳에서 처음 걸리도록 설계한다.
- 도구가 실수를 고쳐 그려 실패가 재현되지 않으면 그림은 그대로 두고, "결과는 매번 다르니 직접 확인하라"는 사례로 설명한다. 잘못된 모습은 실험 패널에서 볼 수 있게 연결한다.
- 그림 없이 다루는 사례: **머리 이름 하나로 나이가 달라 보이는 현상**(양쪽 묶음 등 → 어려 보임). 묶는 높이·길이와 성인 나이를 적어 막는다.

## 10. 실험 패널과 연습장

- 외부 라이브러리 없이 SVG·캔버스로 직접 그린다. 패널 코드는 `build/js_*.js`로 나눠 쓰고 빌드 때 `assets/panels.js`로 합친다.
- 조작하면 결과 숫자와 해석 문장이 바로 바뀐다. 실험은 그림이 없어도 모두 동작해야 한다.
- 연습장: 초록 조작판 = 주어진 환경, 파랑 조작판 = 내 결정. 미션은 **직접 조작해야만** 판정한다(`check_missions.py`로 확인).
- 머리카락 가닥 값은 VFX 헤어 도구 낱말(가이드 가닥·채우기·덩어리·곱슬·뻣뻣함·감쇠)과 연결해 설명한다.

## 11. 지식 색인과 꾸러미

- 페이지마다 지식 색인(#kg)과 온톨로지·서지 꾸러미(#export)를 붙인다. 노드 종류: Concept · Method · Application · Analogy · OpenQuestion.
- 표지·그림 현황은 `cover_manifest.json`에 기록한다.
